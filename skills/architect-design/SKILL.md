# 架构设计技能

## 核心架构模式

### 客户端架构
```
┌─────────────────────────────────────────┐
│                View层                    │
│  (UI组件、动画、渲染)                    │
├────────────────────────────────────────┤
│              Control层                   │
│  (用户输入处理、业务逻辑调用)            │
├──────────────────────────────────────────┤
│               Model层                    │
│  (数据模型、网络请求、本地存储)          │
└──────────────────────────────────────────┘
```

### 常用架构模式对比
| 模式 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| MVC | 简单UI | 直观 | 耦合重 |
| MVP | 需要测试 | 可测试、解耦 | 复杂度高 |
| MVVM | 数据绑定 | 双向绑定 | 学习成本 |
| Clean Architecture | 复杂业务 | 高度解耦、测试友好 | 文件多 |
| ECS | 游戏开发 | 数据和表现分离 | 概念复杂 |

### 服务端架构
- **分层架构**：API层 → 业务层 → 数据层
- **微服务拆分原则**：
  - 单一职责
  - 独立部署
  - 松耦合通信
  - 按业务边界而非技术分层

## 设计原则

### SOLIT原则
1. **S**ingle Responsibility：单一职责
2. **O**pen/Closed：开闭原则
3. **L**iskov Substitution：里氏替换
4. **I**nterface Segregation：接口隔离
5. **D**ependency Inversion：依赖反转

### 高内聚低耦合
- 模块内：高内聚，相关的放一起
- 模块间：低耦合，通过接口通信
- 评估标准：修改一个模块不影响其他模块

## API设计觀范

### RESTful API设计
```
资源命名：/users/{userId}/orders/{orderId}
HTTP方法：GET(查询) POST(创建) PUT(更新) DELETE(删除)
状态码：200成功 201创建 400客户端错误 401认证失败 404资源不存在 500服务器错误
```

### 设计checklist
- [ ] URL设计清晰，语义明确
- [ ] 正确使用HTTP方法
- [ ] 返回合适的状态码
- [ ] 一致的错误格式
- [ ] 版本控制
- [ ] 安全性(jwt、oauth)
- [ ] 限流策略

## 性能优化

### 前端性能
1. **资源加载**
   - 资源压缩合并
   - CDN加速
   - 懒加载
   - 缓存策略

2. **渲染优化**
   - 减少重排重绘
   - 使用requestAnimationFrame
   - WebGL/Canvas优化
   - UI层级管理

3. **内存管理**
   - 对象池
   - 及时释放
   - 内存泄漏检测

### 后端性能
1. **数据库优化**
   - 索引优化
   - 查询优化
   - 读写分离
   - 分库分表

2. **缓存策略**
   - 多级缓存
   - 缓存失效
   - 缓存穿透

3. **并发处理**
   - 异步处理
   - 消息队列
   - 限流熔断

## 模块拆分方法

### 步骤
1. 识别核心业务能力
2. 实义模块边界
3. 绘制模块依赖图
4. 确定模块接口
5. 评估拆分粒度

### 评估标准
- 模块是否独立？
- 模块间耦合是否最小？
- 接口是否稳定？
- 是否便于单独测试？
